## 项目定位

React Native + Expo（SDK 51 / RN 0.74）手机端，用**裸 TCP**（`react-native-tcp-socket`）连 AEMobile mod 的 44444 端口，
远程监控 GTNH 服务器的 AE2 网络：物品终端（搜索/过滤/排序/网格）、合成计划（生成/确认/提交）、
合成 CPU 监控（实时进度/取消）、服务器监控（全服 TPS/MSPT + 逐世界检测）、聊天（游戏公屏 ↔ 手机）。

**图标不依赖服务器**：物品/流体/源质图标以 base64 PNG 存在三个本地 sqlite 里（`assets/*.db`，物品库 189MB）。
分两种分发方式：服主出「内置包」的 APK，或玩家在首次使用页填图标源在线下载。服务器只提供物品列表/合成数据。

## 关键交互流

1. **浏览**：物品 Tab ← 订阅 `items`（连接即推一次 + 每 600s）→ 网格点物品 → 详情 modal。
2. **合成**：详情页数量 → 请求 `plan`（多条响应回进度）→ PlanReview → 选 CPU（`cpusOnce` 过滤 storage>bytesUsed 且空闲）→ 可选允许缺失 → 请求 `start` → 回列表。
3. **监控**：合成 Tab CPU 卡片（订阅 `cpus`，5s）→ 点忙碌 CPU → 明细弹层（订阅 `details`，5s）→ 可取消。
4. **配置**：设置 Tab 是分组列表，账号与登录 / 服务器列表 / 图标库 / 缓存 / 关于各是一个子页；首次无配置时根页直接就是连接表单（Setup 模式）。

### 三类「不是真物品」的条目（2026-10-29 晚）

物品列表里包含三种特殊行，**显示方式**和**下单用的身份**不一样，修改这部分前先看这张表：

| 行 | 显示 | 下单发什么 | 数量单位 |
|---|---|---|---|
| 普通物品 | 自己的图标/名字 | 原样 `name/meta/nbt` | 个 |
| 流体（`ae2fc:fluid_drop` + NBT `{Fluid}`） | `resolveItem` 换成**容器物品**（单元/桶）的图标和名字，`isFluid=true` | **原始流体滴**（`original_name/original_meta`），不是容器 | mB（1 B = 1000 mB） |
| 源质（`thaumicenergistics:essentia` + NBT `{Aspect}`） | `essentia.db` 的要素贴图 + 中文名，`isEssentia=true` | 原样（服务端按 `AEEssentiaStack` 建栈） | 个 |
| 要素物品（`aspectrecipeindex:aspect` + NBT `{Aspect}`） | 同上，名字/图标不变 | 原样 | 个 |

- `ItemsScreen` 打开详情页时传入的是 `original_name ?? name`：**流体只传容器物品的话，服务端会去计算「硫酸单元」的配方**，那个配方不存在，计划直接失败。
- 详情页按类型换数量快捷键和默认值（流体 1000 mB 起、要素 16 个起），数量上限 5 万只对普通物品生效。

## 启动流程与状态栏（2.0.5 起）

冷启动分三段，三段的底色都是 `colors.bg`（#0B0E14），所以看起来是一次连续的深色启动：

1. **原生窗口**：`Theme.App.SplashScreen` 的 `windowBackground` = `@drawable/splashscreen` → `@color/splashscreen_background`（#0B0E14）。
   此处此前为白色，修改前启动时会出现白色闪烁。
2. **RN 启动页**：`App.tsx` 的 `BootOverlay`（图标 + 字标 + 转圈 + 状态行）盖在最上层，
   主界面 `ready` 且最短停留到点之后，200ms 淡出（不是硬切）。
   `SQLiteProvider` 加载期间渲染 `null`，没有这层覆盖就会露出窗口底色；首次安装（或换了内置包）时它还要把 189MB 的库从 assets 拷进私有目录，实测约 1.7 秒。

   入场动画（3.3.0 起）：图标接住 Android 12 系统 splash 那颗放大中的图标（`assets/boot-icon.png`，
   128dp），放大 → 上移 → 淡入字标/状态行。**三条曲线必须分开**（`pop` / `intro` / `textIn`），
   合成一个进度值会让文字压在还没让开的图标上；**最短停留 `BOOT_MIN_MS` = 900ms**（正常 320ms 就 ready，
   不等待动画完成会被截断一半）。状态行按实际阻塞阶段报告，`bootIntroPlayed` 防止换图标库重挂时重播。

3. **主界面**：`RootNavigator`。

**状态栏**：`<StatusBar style="light" translucent={false} backgroundColor={colors.bg} />`。
`expo-status-bar` 在 Android 上默认 `translucent=true`，内容会画到状态栏底下（列表滚动时文字和时钟叠在一起）；
关闭透明后窗口本身就让出了状态栏高度，各屏再按 `useSafeAreaInsets().top` 补一层内边距，
这样在新版 Android 强制边到边时也不会压到状态栏。五个 Tab 页和首次配置页都做了这个处理，Toast 也按 insets 定位。

> 开发模式下仍然会先看到白底 + Expo 图标的启动画面，那是 **expo-dev-client 自己的加载页**（等 Metro 打包 JS），
> 和 App 的 splash 无关；出 release 包时不存在这一层。release 包的 JS 是预打包的，冷启动只剩上面三段。

## 多账号与线路列表（2.0.4 起）

一个「账号」= 一套连接预设：备注名 + 协议 + 地址 + 端口 + 密码 + 主网。列表里点一下就切换，切换即改当前账号并触发各屏重连。

- **存储**：`accounts.index` 存 id 数组，`accounts.active` 存当前 id，每个账号单独一个 `account.<id>` key（JSON）。
   密码是账号的一部分，所以整条记录放 SecureStore；**SecureStore 单值上限 2048 字节**，因此不能把所有账号写入一个 key。
- **迁移**：索引为空时读旧版的 `server.scheme/ip/port`、`user.uuid`、`user.ae_main_net` 生成第一个账号；
  旧 key 之后不再写入，也不再读取。
- **命名**：`accountLabel` = 备注名 → 线路名 → 地址，列表和设置总览都用它。
- **切换语义**：选中即当前账号。切走前会把当前表单 `upsertAccount` 落盘，避免修改密码未保存即丢失。
- **导航**：`RootNavigator` 用 `enteredRef` 锁住「已进过主界面」，否则切到一个还没配好密码的账号时
  `complete` 变 false，整棵树会回退到首次配置页（账号列表就在那页，不会死锁，但体验很差）。
- **首次配置判定**：`ServerSettingsScreen` 用 `navigation.canGoBack()` 判断自己是不是根路由，
  不能只看 `complete`——主界面里切到未配置账号时 `complete` 也是 false。

线路列表分两层：

| 来源 | 说明 |
| --- | --- |
| 内置 | `serverlist.ts` 的 `BUILTIN_SERVERS`：默认 `mc6.dafeimao.net`（IPv6 线）、`mc.dafeimao.net`（肥猫线）、`mc1.dafeimao.net`（华溪线），端口 44444 |
| 在线 | `servers.json`（默认在自建 Gitea 的 `ae/` 目录），地址可在「设置 → 服务器列表」改，存 SecureStore `servers.list_url` |

- **合并**：`mergeServers` 按 `host:port` 去重，内置在前、在线覆盖同名条目（运营可以改线路名/备注），在线独有的追加在后面。
- **缓存**：在线列表落盘到 `cache/servers-*.json`（分类 `servers`），离线时用上次的结果；地址规范化复用 `urlutil.normalizeRepoUrl`。
- **选择器**：账号页「线路」行打开弹层，选一条即写入地址与端口；列表外的服务器直接手动填写地址即可。

## 服务器连接方式（重要）

- 配置不再是一组扁平 key，而是「账号」记录（见上一节）；`config.tsx` 暴露的 `config` 始终是当前账号。
- **模拟器调试不要用 `adb reverse` 隧道**：MuMu 的 adbd 在大流量下会死锁（触摸失效→shell 无响应）。改用 MuMu NAT 网关直连：模拟器内宿主机 = **10.0.2.2**，Metro 用 `--host lan` 启动，App 内地址填 `10.0.2.2`。
- mock 服务器：`node mock/server.mjs`（44444），见 mock/ 目录注释。

## 三个库：items.db / fluids.db / essentia.db（2026-10-28 起）

原来是一个 `itempanel.db`（物品 + 流体容器）。现在拆成三个，**分开更新**：

| 文件 | 表 | 内容 | 大小 |
|---|---|---|---|
| `assets/items.db` | `item_panel` | 物品名/meta/显示名/图标 | 189MB |
| `assets/fluids.db` | `fluid_container` + `fluid_name` + `fluid_icon` | 流体→容器物品、流体中文名、流体图标 | 2MB |
| `assets/essentia.db` | `aspect` | 源质 tag/中文名/图标（`tint` 列说明图标是否已染色） | 236KB |

**三个库都能在线更新**（`src/iconpack.ts`，2026-10-28 起）：
- 清单 `version.json` 是 schema 2，`items` / `fluids` / `essentia` 各一段（各带 sha256/size/rows）；
  旧清单只有 `icons`，作为 `items` 的别名兼容。
- `pendingKinds(manifest)` 逐个比 sha256，**只下载有变化的那一个**（物品库 186MB，流体/源质各 200KB）。
- 下载到 `SQLite/items-<sha12>.db` / `fluids-<sha12>.db` / `essentia-<sha12>.db`，
  校验大小 + 行数 + `quick_check` 后写入 SecureStore（items 用旧键 `icons.active_db`，
  另两个用 `pack.<kind>.name`），最后清理不再使用的旧包。
- 辅助库换过之后要让 `SQLiteProvider` 重挂才会重新 ATTACH：`App.tsx` 的 provider key
  是 `${dbName}|${auxSignature}`，`auxSignature` 就是两个辅助库当前文件名拼起来的。

装配方式（`src/dbs.ts`）：
- `items.db` 走 `SQLiteProvider` 的 `assetSource`（和以前一样，在线更新也换它）；
- `fluids.db` / `essentia.db` 由 `ensureAuxDbs()` 复制到 `documentDirectory/SQLite/`，
  再在 `SQLiteProvider.onInit` 里用 **`ATTACH DATABASE`** 挂到**同一个连接**上
  （不额外开连接，查询写 `fluids.fluid_container` / `essentia.aspect`）。
- **ATTACH 的路径不能带 `file://`**（`FileSystem.documentDirectory` 是 URI），需要去除该前缀，否则 attach 静默失败。
  但反过来，`FileSystem.getInfoAsync()` **只认 `file://` URI**：传裸路径永远返回 `exists:false`。
  2026-10-29 前这里传的就是裸路径，导致辅助库一次都没挂上（`fluids.*` / `essentia.*` 全部查不到，
  流体退回纯色块、源质退回占位图），因为服务端也发中文名所以一直没暴露。

**索引（关键）**：`item_panel(item_name, item_meta)` 必须建索引。没索引时每次查询都是全表扫 186MB，
实测 800 次查询要 2 分钟以上（App 物品页加载 30–60 秒的主要原因）；建完 800 次只要 **34ms**。
`tools/build_item_icons.py` 和 `tools/split_dbs.py` 建库时都会带上这个索引。

生成脚本：
- 物品：`tools/build_item_icons.py <dumps> --rebuild`
- 源质：`tools/build_aspects.py <mods 目录> [--colors aspect-colors.tsv] [--images aspect-images.tsv] <essentia.db>`
- 流体名：`tools/build_fluid_names.py <GT 汉化> AEMobileApp/assets/fluids.db`

## 传输与缓存（2026-10-27 协议 3.0.0 后）

- **传输**：一条 TCP 连接多路复用所有请求与订阅（`src/net/conn.ts` 的 `tcp` 单例）。
  帧格式 `[len:4B][type:1B][flags:1B][payload JSON]`，契约见 `../AEMobile/doc/传输协议与安全.md` §2。
- **鉴权**：连接建立时 `HELLO → HELLO_ACK(nonce, time) → AUTH(kid, ts, sig) → AUTH_OK`，
  `sig = HMAC(token, "AE2TCP\n<ts>\n<nonce>")`，**token 不在网络上传输**，nonce 每连接一次（防重放）。
- **对时**：`HELLO_ACK.time` 直接给偏移；时钟偏差 > 600s 会收到 `AUTH_FAIL{code:"CLOCK"}`，自动重签一次。
- **请求**：`request(cfg, op, params, onProgress?)`，op 见 `../AEMobile/doc/程序结构.md` 的 TCP 接口一览。
  `plan` 用同一条请求的多条响应（`more:true`）回进度。
- **一次性请求走独立短连接**：`request()` 内部用 `requestOnce()`（HELLO→AUTH→REQ→关闭），
  不使用共享长连接 —— 否则设置页（未保存的表单配置）会和屏幕里的订阅流互相强制断开对方连接，
  表现为「测试连接成功、获取网络列表失败」。
- **⚠️ Hermes 下 Buffer 的已知问题**：`buf.subarray(a,b).toString('utf8')` 会退化成 `Uint8Array.toString()`
  （返回 `"123,34,..."`），JSON 解析必失败。解码一律用 `buf.toString('utf8', start, end)`。
- **订阅**：`openStream(cfg, op, params)` 返回 EventSource 形状的对象（`addEventListener('message'|'error')` + `close()`），
  `message` 的 `ev.data` 就是帧对象，直接喂 `parseFrame`。
- **增量帧**：三条流都是「首帧 `t:f` 全量 → 之后 `t:d` 只发变化 → 没变化发 `t:k` 心跳」。
  实测（954 条目 / 6 CPU）：items 全量 45KB / 增量 201B，cpus 全量 304B / 增量 134B。
- **推送频率**（服务端）：`items` 每 600s、`cpus` 每 5s、`details` 每 5s、`tps` 每 5s。`mspt` 恒回 `NOT_SUPPORTED:use_tps`。
- **断线续传**：重连时把上次的 `sid` 带回去，服务端 `StreamState` 能接着发增量，避免一次全量传输。
- **自动重连**：连接层统一处理（指数退避 1s→15s），重连成功后**自动重新订阅**并带 sid。
  屏幕层**不再需要**任何重试代码（2.1.0 的 `attachRetry` 已删除）。
- **内存缓存**：`db.ts` 的 `itemCache`(4000)/`fluidCache`、`frames.ts` 的三个 Accumulator、监控页 180 点曲线。
- **落盘缓存**：见下一节，冷启动与离线时先用它出内容。
- **订阅时机**：三个屏幕只在本 Tab 可见时订阅（`useFocusEffect`，切走即 `close()`），物品页 4 分钟内切回且参数未变则不重连。
- **压缩**：v3 不做 gzip（App 侧没有 zlib）。全量帧 45KB 一次、增量帧 200–600B，满足当前需求。

## CPU 自动分配（2.1.0 起）

进「计划确认」页**不需要手动选 CPU**：默认从列表最上面（`idx` 最小）往下，选第一台**空闲且
`storage >= plan.bytesUsed`** 的（`getCraftingCpuInfo.storage` 对 `plan.bytesUsed`，**容量不足则不能下单**，
必须拦截）；手动选择后即切换为手动模式，弹层右上角可切回自动。弹层列出全部 CPU 并标 `忙碌` / `容量不足（差多少字节）` /
可用；CPU 卡片和详情弹层都显示 `容量 X · 并行 N`。

两个真机上的已知问题（48 台 CPU 的服务器才暴露）：**弹层列表必须能滚**（`.map()` 直铺会把标题和按钮推出屏幕，
现在头部固定 + `ScrollView` 限 55% 屏高）；**遮罩不能把面板套在里面**（`<TouchableOpacity style={mask}>`
包住面板时，滑动列表会被当成点遮罩直接关闭，现在遮罩 `absoluteFill` 与面板平级）。

`formatItemCount` 补充了 `P` / `E`：AE2 容量上限接近 `Long.MAX`，只到 `T` 会输出 `8.39e+6T`。

## 本地缓存（2.0.3 起）

`src/cache.ts` 把服务端下发的数据落盘，冷启动/离线时先提供内容，联网后由新帧覆盖。

| 缓存键前缀 | 内容 | 写入时机 | 节流 |
|---|---|---|---|
| `items:` | 订阅 `items` 的物品列表（可合成/全部各一份） | 每帧 | 10s |
| `cpus:` | 订阅 `cpus` 与 `cpusOnce` 的 CPU 列表 | 每帧 | 20s |
| `details:` | 订阅 `details` 的单个 CPU 明细（按 cpuid 分开） | 每帧 | 20s |
| `mspt:` | 监控页 120 点曲线快照 + 最新均值 | 每帧 | 30s |
| `networks:` | 请求 `networks` 的网络列表 | 手动获取时 | — |
| `servers:` | 在线线路列表 `servers.json`（全局，不分服务器） | 手动更新时 | — |

- **作用域**：键里带 `scopeKey(cfg)`（scheme+ip+port+uuid 前 8 位+主网坐标），换服/换主网不会串数据；`networks` 只按服务器区分。
- **文件布局**：`documentDirectory/cache/<分类>-<8位哈希>.json`，内容 `{ v, at, key, data }`。**文件名不能用缓存键原文**：键里有 `://`、`#`、`/`，百分号编码后仍会被文件系统解码成路径分隔符，写入静默失败（2026-10-26 实际发生过，表现为目录建好了但没有文件）。
- **写入**：`writeCache` 对同一键串行（Promise 链），失败只影响下次冷启动，不打断当前使用。
- **读取**：屏幕挂载/切主网时 `readCache` 先载入数据并记录 `at`，UI 显示「离线缓存 · N 分钟前」+ 顶部提示条；收到实时帧后清空 `cachedAt`。用 `liveRef` 防止迟到的缓存读取覆盖刚到的新数据。
- **清理**：设置 → 存储与缓存，可看分类占用、清空数据缓存（不动服务器配置）、清理在线图标库（切回内置库并删除 `SQLite/icons-*.db` 与临时文件）。

## 图标库在线更新（2.0.2 起）

图标库不再只能跟着 APK 走：设置 →「图标库」可以检查更新并下载新库，装完当次生效、无需重启。

- **更新源**：自建 Gitea 仓库 `dsmgtnhupdate` 的 `ae/` 目录（`version.json` + `icons/{items,fluids,essentia}.db`）。默认 `https://git.dafeimao.net/huaxidesu/dsmgtnhupdate/raw/branch/main/ae/version.json`，可用 `EXPO_PUBLIC_ICON_MANIFEST_URL` 覆盖，也可在「图标库」页里直接改（存 SecureStore `icons.manifest_url`）。
- **地址规范化**：`normalizeManifestUrl`（内部走 `urlutil.normalizeRepoUrl`，与在线线路列表共用）把 Gitea 网页地址 `/src/branch/` 换成 `/raw/branch/`，目录地址自动补 `version.json`；填写内容为默认源时按「未自定义」处理，避免「恢复默认」按钮无意义地亮着。
- **打包脚本**：`python buildiconpack.py --out "<...>/ae" --version 2026.10.26-1 --note "..."`（同时产出 `.db` 与 `.db.gz`）。
- **判定**：只比 `sha256`，不比版本号排序。内置库的 sha 写在 `src/bundled.ts`（`embed_pack.py` 生成），**重建 `assets/*.db` 后要重新执行 embed_pack**，否则装完新包还会提示有更新。
- **安装流程**：`createDownloadResumable` 下到 cache → 校验字节数 → 移到 `documentDirectory/SQLite/icons-<sha12>.db` → `openDatabaseAsync` 执行 `count(*)` + `pragma quick_check(1)` + 行数比对 → 写 SecureStore（active_db / meta）→ 通知 App 用新库名重挂 `SQLiteProvider`，同时 `clearDbCaches()` 清掉 db.ts 的模块缓存。
- **回滚**：数据库按 sha 命名，切库只是改 `icons.active_db`，「恢复内置图标库」= 切回 `items.db`；启动时若发现当前库文件不在了也自动回退。
- **为什么下未压缩的 110MB**：gz 版只有 48MB，但 `expo-file-system` 17 没有文件追加 API，纯 JS 解压要 110MB 输出 + base64 中转（峰值 200MB+），低端机容易 OOM。待后续加入原生解压或增量包后再启用 gz。

## 性能：图标与显示名按需加载（2026-10-29）

起因：物品页进入一次要 1.1 秒以上、进程 PSS 190MB。**并非网络慢，而是本地一次查询了整份列表的图标**
（6609 条 ≈ 22MB base64 常驻 JS 堆，真实服务器 17852 条 ≈ 59MB），而且缓存是「超过 800 条就 clear」的假缓存。

### 现在的做法

| 项 | 做法 |
|---|---|
| 图标 | `ResolvedItem.icon` 是原型上的 getter，第一次读才查库；结果进 `ByteLru`（12MB 上限，按 UTF-16 字符数计） |
| 显示名 | 同理惰性（`dname` getter）。网格只画图标和数量，默认视图完全不查询数据库 |
| 批量取名字 | `prefetchNames()`：只在「搜索」或「按名称排序」时调用，一次获取全部；用 `group_concat` 把上万行合并为一个字符串传回 |
| 解析 / 筛选 | 拆成两个 useMemo：`base` 只依赖 `raw`，`rows` 只依赖筛选条件 |
| 排序 | 模块级 `Intl.Collator('zh-Hans-CN')` 单例（`localeCompare(..., 'zh')` 每次比较都现建 collator） |
| 图标组件 | `ItemIcon` 用 `React.memo` 包住，data URI 的 source 对象按 base64 串缓存（400 条） |
| SQLite | `PRAGMA cache_size = -8000`（8MB）；**不要启用 mmap**，见 AI协作.md |
| 覆盖索引 | `idx_item_dname(item_name, item_meta, dname)`：只取 dname 时不用回表读整行 |

### 实测（MuMu，6609 条物品，release 包）

| 指标 | 改前 | 改后 |
|---|---|---|
| JS 启动 → 数据就绪（其中 `resolveActiveDb`） | 1230 ms（895） | **约 320 ms（14）** |
| 列表解析（冷 / 热） | 1111 ms（含 905ms 取名字） | **190 ms / 43 ms** |
| 搜索取名字 | 428 ms | **85 ms** |
| 进程 PSS（空闲 / 滑过 ~700 格） | 190 / 300 MB | **155 / 231 MB** |

`resolveActiveDb` 那 895ms 是每次启动无条件解压内置图标库（189MB）造成的，现在用 SecureStore 记录 sha +
「当前用的是在线包就跳过」两道短路，只在首次安装/换内置包时落地（首启复制 1.7s，之后 24ms）。
落地判断**只看 sha 标记**（`pack.v2.bundled.<kind>.sha`），不比大小 —— `fluids.db` 每次重建都是
2,007,040 字节，按大小会跳过复制却把标记写成新的。

### 还没解决

- **图片解码内存**：图标是 128px PNG，一屏按 40dp 显示，Fresco 仍按 128×128 解码（64KB/张），滑过
  700 格原生堆 +38MB —— **上限固定的缓存，不是泄漏**。不要把库导成 64px：3x 屏上 40dp = 120 物理像素，会模糊。
- `item_panel` 里有重复的 `(item_name, item_meta)`（61761 行 / 59206 个唯一键，
  `gendustry:GeneSample:0` 有 1067 行），批量查询要用 `distinct` 去重。
- 图标库里 668 条物品的 modid 带 `|`（BuildCraft 系），Windows 上目录名会被清洗成 `_`，
  但 `manifest.jsonl` 里记的是原始路径。建库脚本有回退（`_sanitize`），不要手写路径判断。

## 主题与界面布局（2026-10-28 起）

### 三套色板 + 自定义

`src/theme.tsx`：

- `DARK` / `LIGHT` 是手工调整的两套完整色板；`derivePalette(custom)` 用玩家选的四个颜色
  （`bg` / `card` / `text` / `accent`）推导其余全部颜色：
  `surfaceAlt/surfaceHigh/border` = 卡片与文字互混，`textDim/textFaint` = 文字往背景混，
  `accent2` = 强调色转 40° 色相，`*Soft` = 同色 14% 透明。
  深浅由 `bg` 的亮度决定（`isDark`），成功/警告/错误色按深浅取不同明度。
- `ThemeProvider` 把选择存进 SecureStore（键 `ui.theme`，JSON `{mode, custom}`），
  启动时同步读取，因此第一帧即为正确颜色，不会闪烁。
- **换背景色时如果深浅翻转，会自动把卡片和文字一起换成配套的**（`autoPair`），
  否则容易配置出「浅底浅字」组合，导致界面内容不可见。主题页还有对比度提醒（< 3 报警）。

### 样式编写规则（重要）

颜色是运行时变量，所以**样式表不能在模块加载时硬编码**：

```tsx
// ✅ 现在这样写
const styles = themedStyles((colors) => ({
  screen: { flex: 1, backgroundColor: colors.bg },
}));

export default function Foo() {
  const { colors } = useTheme();   // ① 获取当前色板 ② 主题变化时触发重渲染
  ...
}
```

- `themedStyles` 返回一个 Proxy：内部按主题版本号缓存 `StyleSheet.create(factory(palette))`，
  主题一变，下一次取 `styles.xxx` 自动重建。写法与原来的 `StyleSheet.create({...})` 完全一样，
  只是颜色改为从参数获取。
- **组件里必须调 `useTheme()`**，否则主题切换时它不会重渲染，样式还是旧的。
- 需要颜色但不在样式表里（图标颜色、图表配置等）直接用 `useTheme().colors`。
- `theme.tsx` 还导出 `card`（卡片外观）作为 **live binding**，主题切换时会重新赋值，
  所以 `style={[card, ...]}` 这种用法不用改。
- 颜色工具：`mix` / `alpha` / `luminance` / `isDarkColor` / `rotateHue` / `contrastRatio` / `autoPair`。

### 网格布局与浏览方式

- `src/gridprefs.tsx`：`{columns: 2–8, rows: 2–12, mode: 'scroll' | 'page'}`，存 SecureStore 键 `ui.grid`，
  提供 `useGrid()`（`prefs` / `pageSize` = columns × rows / `setColumns` / `setRows` / `setMode` / `reset`）。
  **`mode` 默认 `'scroll'`（无限下滑）**，旧版本的记录没有这个字段，读取时也按 `scroll` 处理。
- **格子固定宽度**：`tileSize = floor((屏宽 − 左右内边距 − 列间距) / 列数)`，
  每个格子显式 `width/height`，不再用 `flex: 1 + aspectRatio`。
  这样最后一行不满时剩下的物品保持原尺寸，不会把最后一个物品拉宽占满整行。
- **无限下滑（默认）**：`FlatList` 直接使用整份 `rows`，按行虚拟化；
  右下角两个悬浮按钮分别 `scrollToOffset(0)` / 计算总高度后滚到底。
  列表底部有「共 N 个物品 · 已经到底了」。`getItemLayout` 按「固定行高 = tileSize + 行间距」计算。
- **翻页（设置 → 外观 → 翻页浏览，或界面布局页）**：`FlatList` 只吃当前页 `rows.slice(...)`，
  底部翻页条左侧上一页、右侧下一页，**中间页码是按钮，点开输入页码可直接跳转**。
  筛选/排序/列数/行数/浏览方式变化都会回到第 1 页。
- 图标尺寸按格子宽度算（`tileSize * 0.52`，14–40 之间），列多了自动缩小。
- 两个入口：物品页右上角的网格按钮、设置 → 外观 → 界面布局（同一个 `LayoutScreen`）。
- 设置总览的「外观」里另有「翻页浏览」开关，和布局页里的分段按钮读写同一个 `mode`。
